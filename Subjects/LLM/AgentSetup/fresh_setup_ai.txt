1. PROJECT END GOAL (why anything is installed)
------------------------------------------------------------------------
Team of 6 (user rehearses on 3 PCs). Any machine can be orchestrator;
others are workers. There is NO special “slave Hermes mode”.

  Tailscale  — every machine on the SAME team tailnet
  Ollama     — worker; :11434 reachable at that PC’s Tailscale 100.x
  LiteLLM    — localhost :4000; role names → peer Tailscale Ollama IPs
  Hermes     — only when that person drives; talks to local LiteLLM
               http://127.0.0.1:4000/v1 (never to a peer’s Hermes)

“Slave” = that box’s Ollama answers HTTP. Hermes delegate_task stays
inside the Hermes process you opened; it does not start Hermes on peers.

Repo role routing (litellm-config.yaml + compose extra_hosts):
  architect, techlead, coder, tester, docs, deployer, worker(pool)
  NODE_A_IP … NODE_F_IP in .env = Tailscale IPs of the six Ollama nodes.

------------------------------------------------------------------------
2. HARD RULES (never violate — learned on home PC)
------------------------------------------------------------------------
R1. NEVER set User or Machine OLLAMA_HOST permanently to a Tailscale 100.x
    address. That made ollama list / Hermes dial 100.x and time out while
    nothing listened on localhost. Clear both scopes if set.
R2. Hermes model.base_url is ALWAYS 127.0.0.1 — first
    http://127.0.0.1:11434/v1 (direct Ollama), later
    http://127.0.0.1:4000/v1 (LiteLLM). NEVER http://100.x:11434/v1.
R3. Tailscale 100.x belongs in: .env NODE_*_IP, peer curls, fleet map.
R4. When exposing Ollama to Docker/peers: session-only
      $env:OLLAMA_HOST = "0.0.0.0:11434"
    then ollama serve. Prefer 0.0.0.0 over permanent 100.x (README’s 100.x
    serve pattern conflicts with R1; use 0.0.0.0 + Tailscale IP in .env).
R5. Do NOT put Ollama or Hermes in Docker. Docker is for LiteLLM only.
R6. Do NOT install LiteLLM “in WSL” as a separate project. Use
    docker compose from the repo on Windows (Docker Desktop / WSL2 backend
    is fine; workspace stays on Windows paths).
R7. Set OLLAMA_MODELS to the data-drive models folder BEFORE first Ollama
    start, or models land on C:\Users\<you>\.ollama\models.
R8. qwen2.5-coder:7b rejects “thinking” → HTTP 400. In interactive hermes:
      /reasoning none --global
    hermes config set agent.reasoning_effort does not stick reliably.
R9. Quit Ollama via tray (^ → Quit Ollama). App respawns if you only kill
    one process. New PowerShell after changing User env vars.
R10. Hermes install: Blank Slate (option 3), NOT Nous Portal Quick Setup.
R11. Do not hermes update while copying/rehearsing the setup.
R12. Ollama has no auth — firewall :11434 to Tailscale/trusted only.
R13. Windows curl to localhost may hang behind a proxy. Use:
      curl.exe --noproxy "*" ...
    or Invoke-RestMethod. For JSON POST bodies in PowerShell, prefer
      curl.exe ... --data-binary @smoke-body.json
    ( -d $body often produces Invalid JSON).

6. PROCEDURE — WORKER-ONLY (recommended first on PC2/PC3)
------------------------------------------------------------------------

### 6.1 Tailscale
- Download Windows amd64 .msi from https://pkgs.tailscale.com/stable/#windows
  (not the .exe; use ARM MSI only on ARM)
- Install; login to SAME team tailnet (optional: different Google account)
- Verify:
    tailscale status
    tailscale ip -4
  Must show Logged in, a unique 100.x, and ideally home PC visible
  (desktop-gp6fdne / 100.96.116.71).
- Do NOT create a separate private home-only tailnet for rehearsal.

### 6.2 Folders + OLLAMA_MODELS (before first Ollama start)
  New-Item -ItemType Directory -Force -Path "$PROGRAMMER_ROOT\Ollama"
  New-Item -ItemType Directory -Force -Path "$PROGRAMMER_ROOT\Ollama\models"
  [Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "$PROGRAMMER_ROOT\Ollama\models", "User")
  New PowerShell window. Confirm:
  [Environment]::GetEnvironmentVariable("OLLAMA_MODELS", "User")
  Confirm User + Machine OLLAMA_HOST are empty:
  [Environment]::GetEnvironmentVariable("OLLAMA_HOST", "User")
  [Environment]::GetEnvironmentVariable("OLLAMA_HOST", "Machine")
  If Machine set: Admin PowerShell → SetEnvironmentVariable OLLAMA_HOST $null Machine

### 6.3 Install Ollama on data drive
  $env:OLLAMA_INSTALL_DIR = "$PROGRAMMER_ROOT\Ollama"
  irm https://ollama.com/install.ps1 | iex
  New window:
  ollama --version
  (Start serve if needed)
  & "$PROGRAMMER_ROOT\Ollama\ollama.exe" serve
  Other window:
  curl.exe --noproxy "*" -s --max-time 10 http://127.0.0.1:11434/api/tags
  Expect JSON (models may be empty). $env:OLLAMA_HOST must be empty /
  not 100.x.

### 6.4 Pull model + local pong
  ollama pull qwen2.5-coder:7b
  ollama run qwen2.5-coder:7b "Reply with the single word: pong"
  Confirm files under $PROGRAMMER_ROOT\Ollama\models (not only under
  %USERPROFILE%\.ollama\models).

### 6.5 Expose as Tailscale worker (session only)
  Tray: Quit Ollama.
  $env:OLLAMA_HOST = "0.0.0.0:11434"
  & "$PROGRAMMER_ROOT\Ollama\ollama.exe" serve
  Leave window open. Expect Listening on [::]:11434 or 0.0.0.0:11434.
  Verify on THIS PC:
    curl.exe --noproxy "*" -s --max-time 10 http://127.0.0.1:11434/api/tags
    curl.exe --noproxy "*" -s --max-time 10 http://<this-pc-tailscale-ip>:11434/api/tags
  Verify FROM home PC (or orchestrator):
    curl.exe --noproxy "*" -s --max-time 10 http://<peer-tailscale-ip>:11434/api/tags
  Optional: Windows Firewall allow TCP 11434 from Tailscale interface only.

WORKER-ONLY DONE when peer curl from orchestrator returns the model list.

7. PROCEDURE — FULL ORCHESTRATOR (add after worker works)
------------------------------------------------------------------------

### 7.1 Docker Desktop
- Install from Docker’s Windows installer (brings WSL2 backend).
- Verify:
    docker --version
    docker compose version
    docker run --rm hello-world
- Disk for Docker images often on C:; that is OK. Do not use Docker’s WSL
  distro as the project workspace.

### 7.2 Clone / copy the repo
- Need: docker-compose.yml, litellm-config.yaml, .env.example, docs/
- Create .env (never commit):
    Copy-Item .env.example .env
  Fill:
    LITELLM_MASTER_KEY = "sk-" + [guid]::NewGuid().ToString("N")
    NODE_A_IP … NODE_F_IP = Tailscale 100.x of fleet members
  Local smoke on a single box: set all six NODE_* to THIS PC’s 100.x.
  Multi-box: split IPs across peers (same mapping on every orchestrator’s
  .env, or shared fleet file).

### 7.3 litellm-config models
- Team target: llama3.1:8b on architect/techlead/docs;
  qwen2.5-coder:14b on coder/tester/deployer/worker.
- Rehearsal on small GPUs: temporarily set all ollama_chat/* to
  qwen2.5-coder:7b (home PC did this). Mark clearly; restore before submit.
- Compose mounts litellm-config.yaml and MUST pass --config (already in
  docker-compose.yml).

### 7.4 Start LiteLLM
  Ollama must be on 0.0.0.0 (section 6.5) so the container can reach the
  host via Tailscale IP in extra_hosts (127.0.0.1 inside container ≠ host).
  cd <repo>
  docker compose up -d
  $key = (Get-Content .env | Where-Object { $_ -match '^LITELLM_MASTER_KEY=' }) -replace '^LITELLM_MASTER_KEY=',''
  curl.exe --noproxy "*" -s --max-time 30 http://127.0.0.1:4000/v1/models -H "Authorization: Bearer $key"
  Expect ids: architect, techlead, coder, tester, docs, deployer, worker

  Chat smoke (prefer file body on PowerShell):
  Set-Content smoke-body.json '{"model":"coder","messages":[{"role":"user","content":"Reply with the single word: pong"}]}'
  curl.exe --noproxy "*" -s --max-time 180 http://127.0.0.1:4000/v1/chat/completions -H "Authorization: Bearer $key" -H "Content-Type: application/json" --data-binary @smoke-body.json
  Expect message content pong.

### 7.5 Hermes (native Windows)
  Prerequisites: git; whatever the installer asks (uv/python/node).
  irm https://hermes-agent.nousresearch.com/install.ps1 | iex
  Wizard:
    - Choose 3 Blank Slate (NOT 1 Nous Portal)
    - Provider: Custom endpoint (enter URL manually) — option ~40 in long list
    - First: API base http://127.0.0.1:11434/v1 , model qwen2.5-coder:7b,
      key blank/local; prove pong BEFORE pointing at LiteLLM
    - Display name: something local
    - Terminal backend: keep local
    - Toolset: start with everything disabled (or as preferred later)
  After install:
    hermes config get model
    Must be provider custom, base_url 127.0.0.1:11434/v1 initially.
  Reasoning:
    hermes
    /reasoning none --global
    then pong test.
  Optional context (Hermes may demand >=64k; non-blocking if pong works):
    hermes config set model.context_length 65536
    hermes config set model.ollama_num_ctx 65536
    User env OLLAMA_CONTEXT_LENGTH=65536 was tried on home PC.
  Do not hermes update yet.
  Known fail: `ollama launch hermes` timed out — use official install.ps1.

### 7.6 Point Hermes at LiteLLM (only after :4000 chat smoke works)
  hermes config set model.base_url http://127.0.0.1:4000/v1
  hermes config set model.api_key <same as LITELLM_MASTER_KEY>
  hermes chat -q "Reply with the single word: pong" -m coder
  Rollback if broken:
  hermes config set model.base_url http://127.0.0.1:11434/v1

FULL ORCHESTRATOR DONE when Hermes -m coder pongs via :4000.
