JEg spurgte derefter grok hvilken model den ville anbefale til svake laptops fro coding. fik svaret:

On a weak laptop the rule is simple: pull the smallest coding-specialized model that still writes usable code, then keep context short. Bigger models will load, then crawl or swap your machine to death.
Assume “weak” means 8 GB RAM (maybe 16 GB if you are lucky), little or no dedicated GPU, and the OS + IDE already eating a few GB.
Start with these
Best first pull (most people):
Bashollama pull qwen2.5-coder:7b
~4.7 GB download. This is still the workhorse local coder for 8 GB class machines: functions, refactors, explanations, tests.
If 7B is too slow or RAM spikes:
Bashollama pull qwen2.5-coder:3b
~1.9 GB. Noticeably weaker on multi-file reasoning, but fine for snippets and “what does this function do?”

A 14B Q4 file is ~9 GB. On 16 GB that can run, but the OS + VS Code + browser will fight it. On 8 GB it will swap.
Practical setup
Bash# daily coding chat
ollama run qwen2.5-coder:7b

# see what is loaded and how much RAM it uses
ollama ps
Keep context modest (num_ctx 2048–4096). Long context is what kills weak laptops, not just parameter count.
Use the model from an editor (Continue.dev, Cline, Aider, Zed) rather than pasting whole repos into the terminal.
Do not start with CodeLlama. Qwen2.5-Coder at the same size is simply better at code now.
What “usable coding” means at this size
A 3B–7B local model will:

write small functions and boilerplate
explain and comment code
generate tests for one file
suggest fixes when you paste the error

It will not reliably:

refactor a whole project
hold a large repo in context
match Claude / GPT-class multi-file agents

That is a hardware limit, not an Ollama setting.
If you tell me your exact RAM (and whether you have any NVIDIA/AMD GPU or Apple Silicon), I can narrow this to one primary model and one autocomplete model.
